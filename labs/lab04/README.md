# Лабораторна робота №4

**Тема:** Інтеграція із зовнішніми Web API та автоматизоване тестування Python-коду

**Варіант:** 13

## 1. Встановлення залежностей

Для виконання лабораторної роботи використовується Python 3.12 або новіший.

Необхідні бібліотеки: `requests`, `pytest`, `ruff`.

Встановлення залежностей із кореневої директорії репозиторію:

```bash
python -m pip install -r requirements.txt
```

## 2. Правило варіанта 13

Програма аналізує інформацію про вразливості з National Vulnerability Database (NVD), використовуючи оцінку CVSS 3.1.

Параметри правила:

- Порогова оцінка: `6.0`
- Поле: `integrityImpact`
- Очікуване значення: `LOW`

Умова відбору: оцінка CVSS повинна бути не меншою за 6.0, а значення поля `integrityImpact` має дорівнювати `LOW`.

Якщо обидві умови виконуються, результат аналізу — `review`. Якщо даних достатньо, але хоча б одна умова не виконується, результат — `other`.

## 3. Запуск програми

Усі команди виконуються з кореневої директорії репозиторію `cybersecurity-python-labs`.

### 3.1. Локальний режим

Запуск із синтетичним JSON-файлом без підключення до інтернету:

```bash
python -m labs.lab04.main --cve CVE-2099-10001 --input labs/lab04/data/nvd_sample.json
```

### 3.2. Режим NVD API

Отримання інформації про реальну вразливість:

```bash
python -m labs.lab04.main --cve CVE-2021-44228
```

У цьому режимі програма надсилає HTTP GET-запит до NVD API.

За потреби API-ключ передається через змінну середовища `NVD_API_KEY`.

## 4. Формат JSON-звіту

Програма виводить JSON-об'єкт із такими полями:

- `cve_id` — ідентифікатор CVE.
- `variant` — номер варіанта.
- `description` — опис вразливості.
- `vuln_status` — статус запису NVD.
- `cvss_version` — версія CVSS.
- `score` — оцінка CVSS.
- `score_source` — джерело оцінки.
- `vector` — вектор CVSS.
- `rule` — параметри правила варіанта.
- `observed` — фактичне значення поля варіанта.
- `decision` — результат аналізу.

Можливі значення `decision`:

- `not_found` — запис CVE не знайдено.
- `rejected` — запис відхилено.
- `insufficient_data` — недостатньо даних для аналізу.
- `review` — виконуються умови правила варіанта.
- `other` — даних достатньо, але правило не виконується.

Відсутні значення у звіті відображаються як `null`.

## 5. Перевірка програми

### 5.1. Автоматизоване тестування pytest

Запуск усіх тестів лабораторної роботи:

```bash
python -m pytest labs/lab04/tests -v
```

### 5.2. Статична перевірка Ruff

```bash
ruff check labs/lab04
```

### 5.3. Перевірка форматування Ruff

```bash
ruff format --check labs/lab04
```

Автоматизовані тести використовують підміну мережевих запитів, тому виконуються без реального підключення до NVD API.
